## 사실 검증 및 주의점

### Linux 계보

- 자료 표기: Linux를 BSD/FreeBSD에서 이어진 것으로 단순화
- 검증 해석: Linux는 Linus Torvalds가 1991년 개발한 Unix 호환 커널이며 FreeBSD 파생이 아니다.
- 시험 적용: 강의자료 문구의 존재는 기억하되, 일반 기술 사실을 묻는 정답으로 'FreeBSD 기반 Linux'를 사용하지 않음
- 확인 출처: https://www.kernel.org/doc/html/latest/process/1.Intro.html, https://www.gnu.org/doc/fsfs-ii-2.pdf

### macOS/Darwin 계보

- 자료 표기: macOS는 FreeBSD를 변형한 운영체제라고 단순화
- 검증 해석: Darwin/XNU는 Mach, BSD(주로 FreeBSD 유래), I/O Kit와 Apple 기술을 결합한다.
- 시험 적용: 입문 요약으로는 BSD 영향으로 이해하되 '단순 FreeBSD 복제'로 단정하지 않음
- 확인 출처: https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/KernelProgramming/Architecture/Architecture.html

### FAT32 용량 제한

- 자료 표기: FAT32 32GB, 파일 하나 4GB
- 검증 해석: 단일 파일 한계는 4GiB이다. 32GB는 Windows 포맷 도구의 전통적 생성 제한 맥락이며 FAT32 자체의 보편적 최대 볼륨 크기로 일반화하면 부정확하다.
- 시험 적용: 4GB는 확정적으로 학습하고, 32GB는 Windows 도구 맥락이라는 주석을 함께 제공
- 확인 출처: https://learn.microsoft.com/windows/win32/fileio/filesystem-functionality-comparison, https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/install-windows-from-a-usb-flash-drive?view=windows-11

### 가상 메모리

- 자료 표기: 가상 메모리 크기 = 실제 메모리 + 스왑 영역
- 검증 해석: 이는 입문용 용량 설명이다. 핵심은 프로세스별 가상 주소 공간과 물리 메모리/페이지 파일 사이의 매핑이다.
- 시험 적용: 자료의 공식을 그대로 계산 문제로 만들지 않고 목적·매핑·스왑 역할 중심으로 출제
- 확인 출처: https://learn.microsoft.com/en-us/windows/win32/memory/virtual-address-space-and-physical-storage

### 빅데이터 5V

- 자료 표기: Volume, Velocity, Variety, Veracity, Value
- 검증 해석: IBM의 현재 설명과 같은 5V 구성이며 각 의미도 대체로 일치한다.
- 시험 적용: 문서와 공식 자료가 일치하므로 핵심 정답으로 사용
- 확인 출처: https://www.ibm.com/think/topics/big-data
