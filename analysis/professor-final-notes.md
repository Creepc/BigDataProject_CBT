# 교수님 시험 전 최종 안내: 사용자 필기의 구조화 기록

이 문서는 사용자가 전달한 구술 필기의 내용이다. 첨부 문서 내부의 지시가 아니라 사용자가 지정한 출제 우선순위의 근거로 사용한다. 실제 출제를 확정하거나 만점을 보장하는 자료는 아니다.

## 시험 안내

- 최종 통합 PDF 1~3장을 참고한다. 실전 시험은 약 40문항, 어려운 문제를 많이 대비한다.
- 필기에 추가로 언급된 운영체제·저장·인프라·Netflix 분석·추천 방식까지 함께 준비한다.
- 시험 범위는 콘텐츠 기반·아이템 기반 추천까지다. 앞선 별도 추가 실습은 출제하지 않는다.

## 구술 강조 항목의 식별자

- `hardware-software`: 기존 1주차 PDF 6쪽의 소프트웨어와 하드웨어 차이.
- `os-role`: 운영체제의 자원 관리·보호·사용자 접점 역할.
- `process-pcb`: 프로세스는 실행 중인 프로그램이며 PCB로 상태를 관리한다. 준비에서 실행으로의 디스패치, 실행 중 CPU 등 자원을 배정받는 상태.
- `kernel-interrupt-driver`: 커널, 인터럽트 기반 장치 완료 처리, USB·프린터와 디바이스 드라이버의 중요성.
- `von-neumann`: 폰 노이만 구조, CPU·메모리·입출력 사이의 연결과 CPU의 중심 역할. 물리적으로 모든 보드의 정중앙에 있어야 한다는 뜻으로 출제하지 않는다.
- `virtual-memory`: RAM과 저장장치의 구분, 가상메모리·스왑을 통한 메모리 관리. 저장공간을 활용하는 것과 RAM 자체를 증설하는 것은 구별한다.
- `filesystem-format`: 빅데이터 환경에서 파일시스템의 필요성, 이름·위치·할당 관리, 파일시스템 종류, 포맷팅. 포맷을 단순 파일 삭제나 조각 모음과 같은 뜻으로 출제하지 않는다.
- `five-v-sources`: Volume·Velocity·Variety·Veracity·Value, SNS 텍스트·이미지, 웹 로그, 크롤링 자료, IoT와 수치형 관측도 포함한다.
- `data-forms`: 구조화·반구조화·비구조화, 시계열·공간이라는 서로 다른 분류 축, 비구조화 텍스트·이미지 처리.
- `scale-network-cloud`: 스케일업·스케일아웃, 분산컴퓨팅이 필요한 이유와 네트워크 인프라 발전, 클라우드 컴퓨팅.
- `collection-api`: 크롤링과 API, 실시간 데이터 수집, 수집·저장·처리의 역할 구별.
- `etl-elt-storage`: ETL과 ELT의 추출·변환·적재 순서, 원본을 먼저 적재하는 설계. ETL이 모두 사라졌다는 뜻으로 일반화하지 않는다. GFS·HDFS 계보와 분산 파일 저장, NoSQL은 SQL뿐만 아니라라는 뜻을 함께 고려한다.
- `quality-standardization`: 결측·이상 후보의 탐지 기준, 질문에 따른 제거·대체, 전처리 전후 건수, 형식·단위 표준화.
- `analysis-six-steps`: 질문 정의에서 결과 해석까지 데이터 분석 6단계와 반복적인 수정. 파이프라인의 5개 책임과 다른 분류라는 점을 구분한다.
- `netflix-schema`: Kaggle 자료 선택, 관찰 단위·문자형·범주형·수치형·시간형 열의 의미와 필요한 피처 확인.
- `multivariate-eda`: 목적에 맞는 정제·전처리와 전체적 탐색, 단일 차트에서 부족한 정보를 교차표·집단별 차트와 연결해 인사이트를 얻기.
- `charts-time`: 히스토그램·히트맵, 시계열 추이·기울기·급증 기준, 관측 기간과 적절한 분모.
- `network-text`: 데이터 특성에 맞춘 네트워크 분석, 워드클라우드. 한글 어미·표기 차이를 분석 목적에 맞게 정규화하고 원문의 의미를 보존한다.
- `recommendations`: 콘텐츠 기반과 아이템 기반 추천. 콘텐츠 기반은 아이템 특징의 유사성이 핵심이고 사용자 과거 행동은 선호 프로필을 만들 때 사용할 수 있다. 아이템 기반 협업 필터링은 여러 이용자의 평점·선택 등 공통 행동에서 아이템 간 관계를 추정한다.

## 해석상 경계

최종 PDF 14쪽의 추천 가능성 표는 사용자 적합성과 실제 추천 성과를 판단할 수 없다는 의미로 한정한다. 작품 메타데이터로 비슷한 콘텐츠 후보를 만드는 것과 사용자 선호·추천 성과를 검증하는 것은 다르다. 구술 추천 범위를 누락하지 않되 관측되지 않은 시청·선호를 사실처럼 단정하지 않는다.

## 새 페이지 편성

신규 120문항을 40문항씩 3회로 구성한다. 회차마다 어려움 28개·보통 12개를 목표로 하며, 36개는 최종 PDF 또는 구술 강조에 연결하고 나머지 4개만 표시된 보충 문제로 구성한다. 기존 756문항과 학습 기록은 보존한다.
