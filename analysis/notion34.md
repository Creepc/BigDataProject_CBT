# 3·4주차 PDF 전수 분석

두 PDF 총 94쪽을 텍스트 추출과 전 페이지 렌더링으로 교차 확인했다. 94쪽 모두 분석했으며 판독 불가 페이지는 없다. 4주차 68쪽은 푸터만 있는 실질적 빈 페이지다.

## 검증상 주의사항

- 4주차 68쪽은 푸터만 있는 실질적 빈 페이지이지만 렌더링·분석 완료로 기록했다.
- 4주차 66쪽 코드 설명의 개선 MAE 4.19년과 67쪽 표·본문의 4.83년이 불일치한다. 재실행 로그 없이 하나를 확정하지 않았다.
- 4주차 32쪽의 2021년 급락은 연초 수집으로 전체 연도가 포함되지 않은 데이터 한계다.
- 국가·장르 분석에서 첫 번째 값만 main_country/main_genre로 삼는 것은 편의 가정이며 다중값 편향을 만들 수 있다.
- 그래프 해석은 빈도·분포·연관을 설명하며 인과를 자동 주장하지 않는다.

## 핵심 개념

### C01 Scale-up과 Scale-out

- 출처: w3-infra p.2, 3, 4
- 정의: Scale-up은 한 서버의 CPU·메모리·저장을 키우고, scale-out은 여러 범용 서버를 추가해 전체 처리량을 키우는 확장 방식이다.
- 쉽게: 한 대를 더 세게 만드는 것과 팀원을 더 늘리는 것의 차이다.
- 시험 포인트: 수직/수평 확장 정의; 중앙집중형의 네 가지 한계; 장애를 전제로 한 설계
- 오개념: 서버 수가 많기만 하면 자동으로 선형 성능 향상이 생기는 것은 아니다.; scale-out도 네트워크·분산 조정 비용이 있다.

### C02 분산 컴퓨팅과 내결함성

- 출처: w3-infra p.3, 4, 5
- 정의: 여러 노드가 작업·데이터를 나누고 일부 장애에도 서비스를 유지하도록 설계하는 컴퓨팅 방식이다.
- 쉽게: 여러 사람이 일을 나누되 한 사람이 빠져도 전체가 멈추지 않게 하는 구조다.
- 시험 포인트: SPOF 의미; 내결함성은 무장애가 아니라 장애 영향 격리
- 오개념: 복제본이 있으면 백업·일관성·복구 설계가 불필요한 것은 아니다.

### C03 하드웨어 인프라 진화

- 출처: w3-infra p.3, 4, 5, 6
- 정의: 멀티코어 CPU, 분산 메모리, SSD/NVMe, 고속 네트워크, GPU/TPU 등으로 빅데이터 병렬 처리 기반이 바뀐 현상이다.
- 쉽게: 모든 일을 한 종류의 부품에 맡기지 않고 작업에 맞는 부품을 조합한다.
- 시험 포인트: 장치 이름과 역할 매핑; I/O·지연·대역폭 병목 구분
- 오개념: GPU가 모든 연산에서 CPU보다 빠른 것은 아니다.; 메모리 증설만으로 분산 처리 문제가 해결되지 않는다.

### C04 클라우드·컨테이너·엣지

- 출처: w3-infra p.5, 6
- 정의: 클라우드는 탄력적 자원과 관리형 서비스를, 컨테이너는 경량 격리·배포를, 엣지는 데이터 발생지 근처 저지연 처리를 제공한다.
- 쉽게: 빌려 쓰는 큰 데이터센터, 가벼운 포장 상자, 현장 즉시 처리의 조합이다.
- 시험 포인트: 지연·대역폭·비용 요구에 따른 배치; 컨테이너와 VM을 동일시하지 않기
- 오개념: 엣지는 클라우드를 없애는 기술이 아니라 역할을 분담한다.; 컨테이너는 하드웨어 가상화 자체가 아니다.

### C05 웹 크롤링과 스크래핑

- 출처: w3-infra p.7, 8
- 정의: 크롤링은 링크 구조를 탐색해 페이지를 발견하고, 스크래핑은 특정 페이지에서 필요한 데이터를 추출한다.
- 쉽게: 크롤러는 도서관 책 위치를 찾아다니고, 스크래퍼는 책에서 필요한 문장을 뽑는다.
- 시험 포인트: 크롤링/스크래핑 정의; 동적 페이지 도구; 윤리·법률·서버 부하
- 오개념: robots.txt 준수만으로 모든 저작권·개인정보 법적 문제가 자동 해결되지는 않는다.

### C06 REST·GraphQL·API 운영

- 출처: w3-infra p.8, 9
- 정의: REST는 HTTP 리소스 조작 방식이고 GraphQL은 클라이언트가 필요한 필드를 지정하는 쿼리 방식이며, 인증·속도 제한·백오프가 운영 안정성을 보장한다.
- 쉽게: 정해진 메뉴에서 받는 방식과 필요한 재료만 골라 주문하는 방식의 차이다.
- 시험 포인트: over-fetching/under-fetching; 인증과 권한 범위; 429/속도 제한 대응
- 오개념: GraphQL이 항상 REST보다 빠르거나 안전한 것은 아니다.

### C07 실시간 수집과 MQTT

- 출처: w3-infra p.9, 10
- 정의: Webhook·WebSocket·SSE는 실시간 전달 방식이고 MQTT는 IoT용 경량 publish-subscribe 프로토콜이다.
- 쉽게: 사건이 생기면 알려주기, 계속 양방향 통화하기, 서버 방송 듣기, 센서 토픽 구독하기다.
- 시험 포인트: 방향성·연결 지속성 구분; IoT의 경량·저전력 요구
- 오개념: Webhook은 지속 연결이 아니고 WebSocket은 단순 서버 단방향만이 아니다.

### C08 엣지 전처리

- 출처: w3-infra p.6, 10
- 정의: 센서 원본을 클라우드로 모두 보내지 않고 발생지 가까이에서 필터·집계·압축·이상 탐지하는 방식이다.
- 쉽게: 현장에서 중요한 신호만 골라 보내는 데이터 관문이다.
- 시험 포인트: 엣지에서 보낼 통계와 예외 기준 명세; 원본 손실 위험 고려
- 오개념: 전처리로 버린 원본은 사후 분석에 필요할 수 있으므로 보존 정책이 필요하다.

### C09 Full/Incremental Load와 ETL/ELT

- 출처: w3-infra p.11, 12
- 정의: Full Load는 전체를, Incremental Load는 변경분만 적재한다. ETL은 변환 후 적재, ELT는 먼저 적재 후 분석 시 변환한다.
- 쉽게: 이삿짐 전체를 매번 옮길지 바뀐 상자만 옮길지, 정리한 뒤 넣을지 넣고 나중에 정리할지의 차이다.
- 시험 포인트: CDC와 timestamp 증분 차이; ETL/ELT 순서
- 오개념: ELT도 데이터 품질 검증이 불필요한 것은 아니다.

### C10 Kafka와 스트림 처리

- 출처: w3-infra p.12, 13
- 정의: Kafka는 topic을 partition으로 나눠 broker에 분산 저장하는 고처리량 publish-subscribe 스트리밍 플랫폼이다.
- 쉽게: 메시지를 주제별 여러 줄로 나눠 병렬로 전달하는 우체국이다.
- 시험 포인트: partition 역할; 지연 도착 처리; 정확히 한 번 의미
- 오개념: exactly-once 표기는 전체 외부 시스템까지 자동 보장한다는 뜻이 아니다.

### C11 HDFS

- 출처: w3-infra p.14, 15
- 정의: HDFS는 대용량 파일을 블록으로 쪼개 DataNode에 분산·복제하고 NameNode가 메타데이터를 관리하는 분산 파일 시스템이다.
- 쉽게: 큰 파일을 여러 창고에 복제해 두고 중앙 장부가 위치를 관리한다.
- 시험 포인트: 노드 역할; 복제와 내결함성; 초기 SPOF와 개선
- 오개념: NameNode가 실제 모든 데이터 블록 내용을 저장하는 것은 아니다.

### C12 NoSQL 네 가지 모델

- 출처: w3-infra p.15, 16, 17
- 정의: 문서형, 키-값, 컬럼 패밀리, 그래프형은 관계형 제약을 완화하며 데이터 구조·접근 패턴에 맞춰 확장성을 제공한다.
- 쉽게: 문서 서랍, 사전, 넓은 표, 관계망처럼 데이터를 저장하는 네 가지 방식이다.
- 시험 포인트: 요구 질의에 맞는 모델 선택; Cassandra peer-to-peer와 consistency 수준
- 오개념: NoSQL은 SQL을 절대 사용할 수 없다는 뜻이 아니라 Not Only SQL이다.

### C13 오브젝트 스토리지·데이터 레이크·DWH

- 출처: w3-infra p.17, 18, 19
- 정의: 오브젝트 스토리지는 키와 메타데이터로 평면 저장하며, 데이터 레이크는 원본을 schema-on-read로, DWH는 정형 데이터를 주로 schema-on-write로 관리한다.
- 쉽게: 원본을 큰 호수에 모아 필요할 때 해석하는 방식과 미리 정리된 창고에 넣는 방식이다.
- 시험 포인트: schema-on-read/write; 스토리지 클래스; data swamp 방지 요소
- 오개념: 레이크에 넣기만 하면 자동으로 활용 가능한 데이터가 되는 것은 아니다.

### C14 결측·이상·중복·표준화

- 출처: w3-infra p.19, 20, 21
- 정의: 데이터 정제는 결측치, 이상값, 중복, 형식 불일치를 분석 목적과 결측 메커니즘에 맞게 처리하는 과정이다.
- 쉽게: 빈칸·튀는 값·겹치는 기록·서로 다른 표기를 다듬는 일이다.
- 시험 포인트: 처리법 선택 근거; 이상값=오류로 단정 금지; Levenshtein/Jaro-Winkler
- 오개념: 이상값은 실제 극값일 수 있어 자동 삭제하면 안 된다.; 결측 행 제거가 항상 최선은 아니다.

### C15 프로파일링·품질 규칙·드리프트

- 출처: w3-infra p.21, 22
- 정의: 프로파일링은 구조·내용·관계를 요약하고, 품질 규칙은 허용 조건을 명시하며, 드리프트는 시간에 따른 분포 변화를 탐지한다.
- 쉽게: 현재 데이터의 건강검진, 통과 기준, 변화 경보를 함께 운영한다.
- 시험 포인트: 구조/내용/관계 프로파일링 구분; 드리프트가 모델 성능에 미치는 영향
- 오개념: 분포 변화가 곧 데이터 오류라는 뜻은 아니다. 실제 환경 변화일 수 있다.

### C16 메타데이터·카탈로그·거버넌스

- 출처: w3-infra p.22, 23, 26
- 정의: 기술·비즈니스·운영 메타데이터와 데이터 카탈로그를 통해 데이터의 구조·의미·계보·품질·소유권을 관리하는 체계다.
- 쉽게: 데이터 자체뿐 아니라 설명서와 이동 경로, 책임자를 함께 관리한다.
- 시험 포인트: 세 유형 매핑; data swamp 방지; lineage 용도
- 오개념: 메타데이터를 자동 수집해도 비즈니스 의미가 자동 완성되지는 않는다.

### C17 개인정보보호와 다층 보안

- 쉽게: 처음부터 필요한 만큼만 모으고, 다시 알아볼 수 없게 하며, 여러 겹으로 지킨다.
- 시험 포인트: GDPR 핵심 원칙과 권리; 기법별 공격 방어; 동의 요건; Defense in Depth
- 오개념: 단순 식별자 삭제만으로 익명화가 완료되지 않는다.; 동형암호는 성능 오버헤드가 크다.

### C18 데이터 분석 6단계

- 정의: 문제 정의, 데이터 수집, 전처리·정제, EDA, 모델링·분석, 해석·전달의 유기적 과정이다.
